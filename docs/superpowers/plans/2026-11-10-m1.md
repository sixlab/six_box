# SixBox M1 实施计划

> 按 superpowers:executing-plans 在当前工作目录实施。用户已经指定开发基准、技术方案和 M1 范围，无需再次选型。禁止自动开始 M2。

**目标：** 可独立显示的 Tauri 主界面、Rust 运行时管理与可靠的 TypeScript 服务通信。
**架构：** Rust 解析目录并管理单个内置 Node 服务；React 使用受限 Tauri commands 获取状态和重试。服务仅通过父子进程 stdio 通信，不开放网络端口。
**技术：** Tauri 2、Rust、React、TypeScript、pnpm Workspace；macOS arm64；Node 24.22.2。
**基准：** `docs/PRD.md`、`docs/ARCHITECTURE.md`、`docs/POC_REVIEW.md`。

## 全局约束

- 产品 SixBox，开发者 SixLab（六楼实验室），ID `cn.sixlab.box`。
- 只有 Full 内置运行时；不回退系统 Node，不做下载 UI、插件 SDK/市场、MCP、AI、快捷面板。
- 应用数据不写入安装目录；Node 缺失或服务故障不得退出宿主。
- 不自动提交、推送或公开发布。当前为空目录，直接初始化本地 Git 工程。

## 重点故障

1. 内置 Node 缺失、不可执行、版本或架构错误，基础界面仍可用。
2. stdout 非法/超长帧、Ready 超时、请求 ID 错误、管道断开，错误不得吞掉。
3. 服务连续崩溃，退避有上限；手动重试不启动重复服务。
4. 目录不可写、路径占位文件，原文件不被覆盖；日志有大小和保留限制。
5. 退出时服务卡住、父进程关闭，不能留下当前受管服务。
