日期：2026-11-10

## 1. 总体技术架构

采用已经通过 PoC 验证的分层架构：

```text
SixBox Desktop — Tauri 2
│
├── Rust Native Host
│   ├── 单实例与应用生命周期
│   ├── Node.js Runtime Manager
│   ├── 窗口管理器
│   ├── 系统托盘与全局快捷键
│   ├── 系统通知及应用目录
│   └── Node 管理服务启动与恢复
│
├── TypeScript Management Service
│   ├── Plugin Manager
│   ├── Command Registry
│   ├── Config & State
│   ├── UI / API Server
│   ├── Worker Supervisor
│   └── 日志与诊断
│
├── React 主界面
│   ├── 我的工具
│   ├── 运行中心
│   ├── 插件管理
│   └── 设置
│
├── React 快捷启动面板
│
└── 插件运行环境
    ├── 独立 WebView 窗口
    └── 按需启动的 Node Worker
```

**架构原则：**

- Rust 管理操作系统资源和应用生命周期。
- TypeScript 管理插件业务和通用能力。
- 插件只依赖 SixBox SDK，不直接依赖 Tauri API。
- 插件 UI 与后台 Worker 的生命周期相互独立。
- 主程序基础界面不依赖 Node.js 即可启动。
- 不引入额外的独立系统守护进程。
- 首版只运行可信插件，不承诺执行任意不可信代码的安全隔离。

已有 PoC 保留作为验证参考，不迁入 Electron 宿主，也不直接原样复制所有测试代码。

## 3. Node.js Runtime Manager

### 3.1 首版行为

V1.0 优先提供 Full 版本，内置经过验证的 Node.js。

首次启动：

1. Rust 初始化应用数据目录及基础设置。
2. 初始化主窗口、托盘与运行时管理器。
3. 检查内置 Node 可执行文件。
4. 验证其版本、架构和执行能力。
5. 启动 TypeScript 管理服务。
6. 管理服务报告 Ready 后加载已启用插件。
7. 更新主界面的运行状态。

当前 PoC 使用 Node.js 24.22.2。正式项目先以此为兼容基线，并按安全维护需求更新经过测试的补丁版本。

### 3.2 无 Node 时的行为

Rust 主程序不得因为 Node 缺失而退出。

基础主窗口、设置、诊断信息和快捷面板中的主程序操作仍然可用。

依赖 Node 的插件操作显示不可用状态及原因。

V1.0 不要求在线下载、系统 Node 选择或多版本切换。

### 3.3 未来扩展

Runtime Manager 保留以下来源类型：

- `bundled`：随程序安装。
- `managed`：工具箱下载管理。
- `system`：用户系统已有运行时。
- `custom`：用户手动指定。

未来可以实现 Full / Lite 两种发行包，但不改变插件 SDK。

运行时下载目录预留在应用数据目录下的 `runtimes/node/`。

## 4. 宿主、管理服务与 Worker 通信

保留 PoC 已验证的两套通信方式。

### Rust 与 TypeScript 管理服务

使用标准输入/标准输出传输逐行 JSON 消息。

要求：

- 请求必须具有唯一 ID。
- 明确请求、响应、错误和事件格式。
- 定义初始化、Ready、Shutdown 等生命周期消息。
- 请求有超时和错误处理。
- 标准输出只传输协议，日志使用独立通道。
- 禁止静默忽略通信写入失败。

### 管理服务与插件 Worker

使用 Node.js 子进程 IPC。

Worker 统一支持：

- 初始化。
- 接收配置。
- 执行注册命令。
- 发布运行状态。
- 发送心跳。
- 异步停止并清理资源。

Worker 应只使用工具箱提供的 Node 可执行文件。

### 插件 UI 与管理服务

首版延续已验证的本机回环 HTTP 方案。

插件 UI 通过受限 SDK 接口访问自身配置、状态和命令。

必须限制接口权限、请求来源、资源访问范围和窗口导航。

不得向插件 UI 直接暴露管理服务管理员权限或任意 Rust 命令。

当前方案的多插件同源隔离仍有限制，因此只用于可信插件；未来开放不可信插件前，必须重新评估独立 Origin 与原生执行隔离。

## 5. 服务与 Worker 故障恢复

### Worker 故障

保留 PoC 已验证的心跳、重试退避与重试次数上限。

多次恢复失败后进入 Failed 状态，等待用户手动恢复，不允许无限重启。

停止 Worker 时允许执行异步资源清理；超过约定时限后终止进程，并记录原因。

### 管理服务故障

这是正式版必须补齐的能力。

Node 管理服务崩溃时：

1. Rust 主程序保持运行。
2. 主界面显示服务异常状态。
3. 按有限次数和退避策略尝试重启服务。
4. 服务成功恢复后重新扫描插件、重建状态。
5. 重新建立必要的窗口与会话连接。
6. 恢复允许自启动的后台任务。
7. 恢复失败时提供诊断与手动重试。

重启过程不得盲目重复执行已提交的非幂等操作，例如删除文件或覆盖数据。

## 6. 插件清单规范

使用 `manifest.json` 声明插件信息和能力。

初步格式如下：

```json
{
  "schemaVersion": 1,
  "id": "cn.sixlab.network-monitor",
  "name": "网络质量监控",
  "version": "0.1.0",
  "apiVersion": 1,
  "ui": {
    "entry": "ui/index.html",
    "window": {
      "width": 900,
      "height": 600
    }
  },
  "worker": {
    "entry": "worker.cjs",
    "autostart": true
  },
  "commands": [
    {
      "id": "open",
      "title": "打开网络监控",
      "type": "window"
    },
    {
      "id": "checkNow",
      "title": "立即检测网络",
      "type": "worker"
    }
  ]
}
```

这是开发基线格式，具体 Schema 应在实现最小 SDK 时固定并编写自动校验。

规则：

- 插件 ID 唯一且保持稳定。
- 版本采用 SemVer。
- `apiVersion` 用于平台兼容性校验。
- UI 和 Worker 都允许省略。
- 仅声明 Worker 所需的插件才启动后台进程。
- V1.0 默认每个 UI 入口单实例。
- 不允许插件动态注入 Rust 原生代码。
- 不实现通用多语言插件运行时。

## 7. 插件 SDK

SDK 分为 UI 和 Worker 两个入口，共享类型定义。

```text
@sixbox/sdk/ui
@sixbox/sdk/worker
@sixbox/sdk/types
```

正式接口先覆盖以下公共能力：

| 模块 | 责任 |
|---|---|
| App | 获取当前插件身份、版本 |
| Window | 打开、聚焦、关闭本插件窗口 |
| Command | 注册及执行声明的命令 |
| Config | 读取、保存、监听配置变化 |
| State | 发布、获取、订阅运行状态 |
| Notification | 请求发送系统通知 |
| Logger | 统一结构化日志 |
| Lifecycle | Worker 初始化、停止与清理 |

**Config 与 State 必须分离。**

Config 是持久化数据；State 是当前运行状态，默认不要求持久化。

SDK 错误需要使用稳定错误码，插件可以识别运行时不可用、未授权、参数错误、执行超时等情况。

V1.0 不实现通用剪贴板、文件系统、SecretStore、MCP 或 AI SDK。

## 8. Command Registry

Command 是 SixBox 的统一功能调用入口。

插件通过 Manifest 声明可公开的命令，平台负责索引、校验和执行路由。

同一个命令可以由以下入口调用：

- 插件自己的 UI。
- SixBox 快捷启动面板。
- 主程序工具列表。
- 适用的系统托盘菜单。

命令应具有稳定 ID、名称、执行类型和参数定义。

V1.0 快捷面板只需要直接执行无参数命令。复杂参数命令可以打开相应插件窗口处理。

命令执行必须验证插件是否已启用、运行环境是否可用，以及操作是否需要确认。

未来 MCP 可以在 Command Registry 外增加适配层，不需要将 AI 逻辑引入插件核心。

## 9. 插件安装、更新与卸载

### 安装

V1.0 支持可信本地目录及单文件插件包。

建议单文件扩展名使用 `.sixbox`，底层为规范化的 ZIP 包。

安装流程：

校验清单 → 检查兼容性 → 临时目录解包 → 验证文件 → 提交安装 → 注册命令与入口。

安装失败时不得留下半安装状态。

### 更新

V1.0 只支持用户手动选择更新包。

插件程序与插件数据分离。

更新期间停止相关 Worker 和窗口，验证新版本后替换程序，失败时恢复上一可工作版本。

首版对于不兼容的数据结构变更应拒绝更新，不自动执行无法回滚的数据迁移。

### 卸载

先关闭窗口和停止 Worker，再注销命令、移除插件程序。

默认保留用户配置和业务数据；用户明确勾选后才清除相关数据。

禁用和卸载都需要同步更新快捷面板索引。

## 10. 数据存储

所有持久化路径由 Rust 统一解析，Node 管理服务通过初始化信息获取路径。

以 macOS 为例：

```text
~/Library/Application Support/cn.sixlab.box/
├── plugins/
├── plugin-data/
├── settings/
├── data/
└── runtimes/
    └── node/
```

缓存和日志放在系统标准应用缓存、日志目录。

基本要求：

- 插件程序和数据独立。
- 插件数据按 ID 命名空间组织。
- 配置写入采用临时文件和安全替换。
- 配置内容加载前执行校验。
- 损坏配置不得直接覆盖或清空。
- 日志设置保留期限及大小上限。
- 不在日志中默认记录 JSON 输入或完整业务内容。
- 应用升级不清除用户数据。

V1.0 可以优先使用 JSON 与 JSONL 存储基础数据；当业务确实需要查询大量结构化历史数据时再引入 SQLite，不为了目录规划而提前引入数据库依赖。

**敏感凭据：** V1.0 不实现用户密码保险库。未来采用统一 SecretStore，倾向本地加密文件与主密码。

## 11. 主程序与窗口管理

主程序包含：

- 我的工具。
- 运行中心。
- 插件管理。
- 设置。

插件 UI 使用独立 WebView 窗口。

行为规则：

- 关闭主窗口：隐藏，应用保持运行。
- 关闭插件窗口：仅销毁 UI。
- 重复打开已有工具：聚焦原窗口。
- 插件 Worker：独立于 UI 生命周期。
- 完全退出：停止所有 Worker 和管理服务。
- 禁用插件：关闭窗口并停止相关服务。
- 主程序只能运行一个实例。
- 记录窗口尺寸和位置，并在显示器变化时安全恢复。

独立插件托盘图标、同类型多窗口实例暂不进入 V1.0。

## 12. 全局快捷启动面板

使用独立的 Tauri WebView 窗口。

主要规则：

- 快捷键暂定 `Control + Option + Space`。
- 允许用户修改快捷键。
- 快捷键注册失败时显示提示。
- 支持工具、命令、内部设置搜索。
- 支持名称、关键词和别名匹配。
- 支持全键盘操作。
- 处理中文输入法组合输入。
- 隐藏面板不停止后台任务。
- 不重复创建新的快捷面板窗口。
- Node 不可用时仍可执行内置的主程序操作。

面板搜索索引由 Command Registry 提供，插件变化时自动刷新。

## 13. 系统托盘

V1.0 使用统一 SixBox 托盘图标。

最小菜单：

- 打开 SixBox。
- 打开常用工具。
- 查看后台运行状态。
- 暂停或恢复适用任务。
- 设置。
- 完全退出。

菜单必须由主程序管理，不允许插件直接获得完整原生托盘控制权限。

macOS 菜单栏的实际点击、完全退出及后台保持行为必须使用正式构建进行验收。

## 14. 开发与构建规范

- TypeScript 采用严格类型检查。
- 插件使用统一构建模板。
- 插件 UI 构建为静态 Web 资源。
- Worker 构建为目标 Node 版本兼容的 JavaScript。
- 普通插件不要求编写 Rust 代码。
- 最终用户不需要安装 Node.js 或 npm。
- 正式包不内置测试插件的业务源码。
- 开发与正式构建使用相同的插件协议。
- 不为兼容 PoC 临时接口而额外增加长期适配层。
- CI 至少执行类型检查、核心单元测试和插件包校验。

## 15. V1.0 测试与验收

以下测试必须完成：

| 类别 | 核心场景 |
|---|---|
| 启动 | 内置 Node 正常、Node 缺失、Node 启动失败 |
| 单实例 | 重复打开应用不产生第二套管理服务 |
| 插件 | 安装、发现、启用、禁用、更新、卸载 |
| 窗口 | 独立打开、重复聚焦、关闭后 Worker 继续 |
| 后台 | 正常执行、暂停、恢复、异常退出和心跳超时 |
| 故障 | Node 管理服务崩溃和重建 |
| 数据 | 配置保存、损坏配置、更新保留数据 |
| 托盘 | 真实点击、隐藏、打开、完全退出 |
| 快捷面板 | 全局快捷键、搜索、执行、中文输入法 |
| 系统状态 | 睡眠唤醒、网络切换、异常退出 |
| 分发 | macOS arm64 正式构建包运行测试 |

两个真实插件作为端到端验收：

**JSON 工具**：无 Worker，独立窗口，格式化、压缩、校验。

**网络质量监控**：带 Worker，状态展示、阈值检测、暂停恢复、异常提醒、基础历史记录。

首版测试范围以 macOS Apple Silicon 为准。最低 macOS 版本必须经过相应系统实测后才能对外承诺。

## 16. 明确不做的功能

V1.0 不包含：

- Electron 对照版本。
- Windows / Linux 正式发布。
- 插件市场。
- 自动在线更新。
- 不可信插件沙箱。
- Go、Python 等多语言插件运行时。
- Node.js Lite 发行版。
- Node.js 在线下载、手动路径切换。
- 系统级独立 Agent。
- Django 云同步。
- MCP、DSH 专属插件。
- 内置 AI 助手。
- 商业订阅。
- 主密码保险库。

所有以上功能仅保留必要扩展边界，不开发空模块或模拟实现。

## 17. 开发完成定义

SixBox V1.0 完成，不以“所有计划代码已经编写”为标准，而以以下结果为标准：

**用户可以安装 SixBox，通过快捷面板调用工具，安装和管理 TypeScript 插件，使用独立工具窗口，让后台插件长期运行，并且在异常、重启、更新及完全退出时保持符合预期的行为。**

上述核心场景必须使用真实 macOS 正式构建包完成验收。
